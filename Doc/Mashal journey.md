# Mashal journey and levels

Every new daily game completion opens a separate Mashal popup above the entire game screen, including its header. When the game earns a new daily bar, it feeds an ember into the Mashal, makes the flame swell and settle, raises a +1 marker, and fills one segment of the five-game level bar. Completing another demo edition after the same game has already counted today still opens the popup, showing the current progress and an already-counted message, without another +1 or level-up animation. The popup contains a profile icon, display name, level badge, and the consecutive-day streak. Replays, practice, and restored results do not add bars or repeat the celebration.

Neeti's completion popup follows the whole game screen, including its share-card step. Opening the card before the popup's one-second delay no longer cancels the popup; leaving the game still cancels it. Popup visibility uses layout and computed styles so browsers without `Element.checkVisibility()` can still show it for every game.

Level 1 starts at zero completions. Every five new daily game completions earns another level: five means Level 2, ten means Level 3. Completing all five different games on one day earns a level, as does completing the same game's new daily challenge on five different dates. Gaps can reset the separate day streak but retain the earned level. Each game counts at most once per calendar date; switching or refreshing demo editions cannot award another bar for that game on the same date.

The completion ledger is saved in this browser under `db-games:v1:mashal-completions`. Mashal progress survives refreshes and later visits. Demo rounds, result history, preferences, and names still last only for the current visit. If browser storage is unavailable, Mashal progress lasts for the current visit. The Settings reset action clears the saved Mashal level and completion ledger as well as the current rounds.

On a milestone, the bar fills to five, the badge pulses, and the card says “नया लेवल! / Level up!” before settling to zero toward the next level. Earned Mashals gain a gold handle band at Level 2 and an additional sparkle at Level 3. The progress sheet shows the same card in its final state.

Settings includes an optional display-name field. It limits input to 40 characters and treats names as plain text. Until a name is set, the card says “आपकी मशाल / Your mashal.” The icon is a default profile illustration.

Motion lasts 2.6 seconds. Three seconds after the popup opens, “छोड़ने के लिए टैप करें / Tap to skip” becomes visible. Tapping dismisses the popup and reveals the original game result; it does not close automatically. Early taps and Escape leave it open; Escape dismisses it once the skip prompt is available. Reduced-motion preferences show the final visual state directly while retaining the same three-second dismissal timing. The native modal dialog blocks background interaction. Leaving the result or game removes the popup and its timers. Styles are shared between the popup and the progress sheet.

Validation scripts: `tests/mashal-progression.mjs` checks same-day and multi-day levels, gaps, aliases, duplicate guards, demo editions, persistence, reset, and storage fallback. `qa-mashal-journey.mjs` exercises the popup through all five games, replays, restoration, refresh persistence, reset, name escaping, modal timing, Hindi/English, reduced motion, and 320/390/1280-pixel layouts. `qa-torch-state.mjs` checks aborts and exhausted attempts; `qa-torch.mjs` checks completion popups across all five games at mobile and desktop widths. Browser scripts accept `TORCH_QA_URL` for a local server; the journey script starts its own server when omitted.

After `npm run build` and `npm run build:single`, `npm run test:mashal` also checks the emitted single HTML (opened directly and over HTTP) and `dist` assets: all three editions of all five games, route aliases, daily duplicate guards, restored results, supported practice replays, fast Neeti card transitions, exit cleanup, and browsers missing `checkVisibility`. Wordal, Neeti and Jodo use actual input controls; cricket and Carrom use final-score/objective fixtures through their real completion functions. Filter runs with `MASHAL_QA_TARGETS` (`single-file,single-http,dist`) or `MASHAL_QA_SCENARIOS` (`normal,quick,legacy`).
